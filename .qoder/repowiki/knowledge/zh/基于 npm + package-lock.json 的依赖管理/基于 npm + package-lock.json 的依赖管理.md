本项目采用标准的 npm 生态进行依赖管理，核心由 `package.json` 声明依赖、`package-lock.json` 锁定版本，未使用 pnpm/yarn/bun 或 vendor 策略。

**1. 使用的系统与工具**
- **包管理器**：npm（通过 `package-lock.json` lockfileVersion: 3 确认）
- **构建框架**：Next.js 16（导出模式），配合 Tailwind CSS 3、PostCSS、TypeScript 5
- **脚本入口**：`scripts/generate-posts.js` 用于生成静态文章页面，由 `generate-posts` 命令触发

**2. 关键文件与依赖分组**
- `package.json`：集中声明所有依赖，按运行时/开发时清晰分为 `dependencies` 与 `devDependencies`
  - 运行时核心：`next@^16.0.1`、`react@^18`、`react-dom@^18`、`tailwindcss-animate`、`lucide-react`、`marked`、`react-markdown`、`remark-gfm`、`next-themes`、`class-variance-authority`、`clsx`、`tailwind-merge`
  - 开发期工具：`typescript@^5`、`eslint@^8`、`eslint-config-next@14.1.0`、`postcss@^8`、`autoprefixer@^10.0.1`、`ts-node@^10.9.2`、`gray-matter@^4.0.3`、`date-fns@^4.1.0`、`@tailwindcss/typography@^0.5.16`
- `package-lock.json`：锁定全部子依赖树，记录每个包的精确版本、sha512 integrity 校验值及来源镜像地址
- `.gitignore`：忽略 `yarn-debug.log*`、`yarn-error.log*` 等日志，表明团队可能曾混用 yarn，但当前以 npm 为准

**3. 架构与约定**
- **版本范围策略**：生产依赖普遍使用 `^major` 或 `^major.minor` 的 caret 语义化版本（如 `^16.0.1`、`^18`、`^5`），允许小版本自动升级；仅 `eslint-config-next` 固定为 `14.1.0` 无符号，避免与 Next.js 主版本不兼容
- **锁文件提交**：`package-lock.json` 已纳入版本控制，保证多环境安装一致性
- **私有源/镜像**：lockfile 中大量 `resolved` 指向 `https://mirrors.tencent.com/npm/...`，说明本地 npm 配置了腾讯云镜像源（应通过全局 `.npmrc` 或环境变量设置，仓库内未包含 `.npmrc`）
- **无 vendoring**：未使用 `node_modules` 外置或源码级 vendoring，依赖均通过 npm 安装到 `node_modules`
- **模块解析**：`tsconfig.json` 中 `moduleResolution: "bundler"`，适配现代 bundler 场景下的依赖解析行为

**4. 开发者应遵循的规则**
- 新增依赖一律写入 `package.json` 对应字段，不要手动编辑 `package-lock.json`
- 优先使用 `^major` 风格保持可升级性；若某依赖存在破坏性更新风险，改用精确版本号并附注释说明
- 切换包管理器前需统一团队规范（当前项目以 npm 为准，`.gitignore` 残留 yarn 规则建议清理）
- 若需更换 npm 镜像源，应在 CI 或团队文档中明确 `.npmrc` 配置方式，确保 lockfile 中的 `resolved` 地址一致
- 运行 `generate-posts` 脚本前需先执行 `npm install`，因为该脚本依赖 `gray-matter` 等 devDependency
