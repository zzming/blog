## 1. 系统概览
本仓库是一个基于 Next.js Export 模式的纯静态博客/作品集站点，没有运行时环境变量或后端配置服务。配置体系由三类组成：
- 构建期框架配置（next/tailwind/postcss/tsconfig）
- 应用级内容常量（src/config/*.ts）
- 通过脚本从 Markdown 源文件生成的帖子索引（scripts/generate-posts.js → src/config/posts.ts）
不存在 .env*、.yaml/.toml、数据库或远程配置中心；所有可配置项均以 TypeScript 常量形式在编译时注入到产物中。

## 2. 关键文件与职责划分
- 构建与工具链配置
  - next.config.js：Export 模式、关闭图片优化、开启 trailingSlash
  - tailwind.config.js：darkMode=class、typography 插件、扫描路径
  - postcss.config.js：tailwindcss + autoprefixer
  - tsconfig.json / tsconfig.scripts.json：@/* 路径别名、Next 插件、模块解析策略
- 应用内容配置（src/config/）
  - global.ts：站点名、作者、导航、页脚社交链接等全局元信息
  - home.ts：首页问候语与按钮文案
  - about.ts：关于页标题、简介、统计、技能、经历、联系方式
  - projects.ts：项目列表（标题/描述/链接/封面图）
  - contact.ts：联系信息与社交图标列表
  - content.ts：聚合型配置，包含站点名、多语言文案、首页/项目/博客/关于的 UI 文案及示例数据
  - posts.ts：自动生成 的博客文章索引（含 markdown 源码与 HTML 片段），首行注释明确禁止手动编辑
- 生成脚本
  - scripts/generate-posts.js：读取 src/posts/*.md，渲染为 HTML，输出 src/config/posts.ts
- 类型定义
  - src/types/post.ts：Post 接口，被 posts.ts 引用以提供类型安全

## 3. 架构与设计约定
- 按页面域拆分配置文件：每个路由域（home/about/projects/contact/posts）对应一个独立模块，便于定位与维护。
- 全部使用 as const 对象字面量导出：确保编译器能推断出精确的字面量类型，避免运行时修改。
- Markdown 与 JS 配置解耦：文章内容放在 src/posts/*.md，通过脚本生成 posts.ts；其他静态文案直接写在 TS 文件中，无需额外加载器。
- 无运行时配置加载逻辑：组件直接 import 对应 config 模块，不存在统一 ConfigService、环境变量注入或运行时合并层。
- 主题切换通过 class 驱动：Tailwind 的 darkMode: 'class' 配合 React Context（src/context/ThemeContext.tsx + ThemeProvider.tsx）实现，不在配置文件中声明颜色值。

## 4. 开发者应遵循的规则
1. 新增页面配置：在 src/config/ 下新建同名模块，导出 xxxConfig 常量对象，并在组件中直接 import。
2. 不要手动编辑 posts.ts：该文件由脚本生成，任何对文章结构的改动都应更新 src/posts/*.md 并重新运行生成脚本。
3. 保持 as const 风格：所有配置对象都应以 as const 结尾，以便获得最佳类型推断。
4. 敏感信息不入库：由于是静态站点，不应将密钥写入任何配置；如需外部 API Key，应在部署平台的环境变量中注入并通过构建期替换（当前仓库未启用此流程）。
5. 路径别名统一使用 @/*：通过 tsconfig 的 paths 映射到 src/*，避免相对路径嵌套过深。
6. 新增 Tailwind 样式扩展：在 tailwind.config.js 的 theme.extend 中追加，而非创建新 CSS 文件。
